# Reproducing the MontePilot manuscript

This snapshot contains the software and machine-readable evidence evaluated in
the manuscript. Runtime results are hardware- and environment-specific; new
machines should reproduce the statistical summaries closely but will produce
new timings.

Because the hardware evidence was collected during development, the article
reports the release that generated each result. `RESULT_PROVENANCE.md` maps
every manuscript evidence block to its generating release, exact archived
source bundle, and machine-readable output. The three earlier source bundles
are retained under `archived_versions/`; the CPU-only Q5--Q6 experiments were
generated by the 0.6.1 tree. Version 0.6.2 adds the frozen logistic-IRLS and
CUDA pre-submission benchmark protocol without relabeling earlier evidence.

## Archived evidence

- `results/publication_fp32_v051/` contains the matched-FP32 generic benchmark
  report, calibrated warm runs, fresh-process runs, numerical validation, and
  speedup summaries from the Intel Arc 140V workstation.
- `results/application_v060/` contains the corresponding psychometric and
  cluster-randomized-trial application benchmark files.
- `docs/current_hardware_results/controlled_precision_v052/` contains the
  five-seed controlled-input suite: 60 comparisons, all passing.
- `results/supplementary_experiments.json` contains the hardware-independent
  variance stress test, adaptive-stopping demonstration, checkpoint recovery,
  and analytic checks.

## Base installation and tests

```bash
python -m pip install -e ".[research]"
python -m unittest discover -s tests -v
montepilot doctor
```

The base NumPy test suite contains 45 tests. Optional accelerators require the
appropriate PyTorch build and device drivers.

## Recreate controlled-input validation

```bash
python benchmarks/validate_precision.py \
  --profile full \
  --precision float32 \
  --output-dir precision_validation_results
```

## Recreate the publication benchmark

```bash
python benchmarks/benchmark_publication.py \
  --profile full \
  --precision float32 \
  --min-block-seconds 0.5 \
  --output-dir publication_benchmark_results
```

Application-only benchmarking can be requested with:

```bash
python benchmarks/benchmark_publication.py \
  --profile full \
  --precision float32 \
  --workloads psychometric_alpha_n1000_k20 cluster_trial_j100_m30 \
  --min-block-seconds 0.5 \
  --cold-start-repeats 0 \
  --output-dir application_benchmark_results
```

## Recreate supplementary CPU experiments

```bash
python benchmarks/supplementary_experiments.py
```

This script writes `supplementary_experiments.json` in the current directory.

## Reported environments

The primary accelerator experiments used Windows 11 build 26300, Python
3.11.17, NumPy 2.4.6, PyTorch 2.14.1+xpu, and an Intel Arc 140V integrated GPU
reporting 16 GB shared memory. CPU model, memory configuration, power mode,
thread counts, and driver version were not captured and therefore cannot be
reconstructed after the fact.

The archived supplementary CPU output reports Linux, Python 3.12.14, NumPy
2.3.5, and MontePilot 0.6.1. SciPy is required by the analytic checks. The
new 0.6.2 runs capture their own environment in machine-readable form.

## Precision and interpretation

All backends in the publication throughput comparison requested float32.
Controlled-input validation compares identical inputs against a NumPy float64
reference. Do not compare unmatched default precisions as if the difference
were attributable only to hardware.

Warm-state timings exclude interpreter startup and most device initialization.
Fresh-process timings include Python startup, imports, backend initialization,
computation, and process exit. Neither timing boundary is a hardware-cold
measurement because operating-system and driver caches may persist.
