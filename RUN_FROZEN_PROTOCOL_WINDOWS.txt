MontePilot 0.6.2 frozen-protocol workflow (Windows / Anaconda Prompt)
==================================================================

Read docs/FROZEN_PROTOCOL_EXECUTION.md for the complete audit procedure.
The original protocol tag already exists. Do not recreate or move it.

1. Obtain a fresh checkout with byte-preserving line endings

git clone -c core.autocrlf=false https://github.com/subirhait/montepilot.git
cd montepilot
git fetch origin --tags
git checkout --detach <reviewed-launcher-commit>
git rev-parse HEAD
git cat-file -t refs/tags/protocol-v0.6.2
git rev-list -n 1 refs/tags/protocol-v0.6.2
git status --short

Replace <reviewed-launcher-commit> with the reviewed hardened-launcher SHA.
The tag type must be "tag" and the resolved commit must be:
8fd8a3eb61e24fc66f73d4e704e5b699f72ac5cd
Do not launch from the old protocol tag: its runner lacks these safeguards.

2. Activate the intended environment and install

conda activate montepilot
python -m pip install -e ".[research]"
python -m montepilot.cli doctor
python -m unittest discover -s tests -v

Install the appropriate XPU PyTorch build/drivers. Doctor must list numpy,
torch_cpu, and torch_xpu. Full runs require a clean tracked checkout. The
supplied JSON and all calculation source must match the frozen bytes.

3. Smoke test (diagnostics only; use a fresh output path for every retry)

python benchmarks\run_frozen_protocol.py --phase laptop --smoke --output-dir protocol_v062_laptop_smoke

Inspect logs, requested backends, all conditions, and numerical validation.
Stop and fix the environment if XPU or Torch CPU is unavailable. Smoke timings
and estimates are not manuscript evidence.

4. Full laptop run and verification

python benchmarks\run_frozen_protocol.py --phase laptop --output-dir protocol_v062_laptop_full
python benchmarks\verify_checksums.py protocol_v062_laptop_full

Inspect run_identity.json: status completed, smoke false, protocol_commit and
execution_source_commit both equal the frozen hash. executing_commit records
the separate reviewed launcher revision. Check configuration/source/launcher
hashes and inspect all reports, including failures. Completion alone does not
prove numerical validation or hardware coverage passed.

Keep the unchanged directory and ZIP. Record the ZIP hash using PowerShell:
Get-FileHash protocol_v062_laptop_full.zip -Algorithm SHA256

Archive all raw reports, environment/provenance records, logs, frozen source,
configuration, launcher, and checksum manifest. Only then update the pending
laptop row in RESULT_PROVENANCE.md with the archive and both revision IDs.
